## 一、项目概述

基于 Qt 框架开发的医院门诊预约管理系统，包含以下功能模块：
- **门诊管理**：查看、添加、编辑、删除门诊信息
- **预约管理**：预约门诊、查询预约、取消预约
- **数据持久化**：JSON 格式存储，支持旧 txt 格式自动迁移
- **UI 界面**：双表格布局、按钮分组、状态栏统计、查询区域可展开/收起

### 项目文件结构

```
1/
├── main.cpp                  # 程序入口
├── mainwindow.h/cpp          # 主窗口（UI事件、数据持久化、查询逻辑）
├── mainwindow.ui             # 主界面布局
├── clinic.h/cpp              # 门诊数据类（含预约列表封装）
├── appointment.h/cpp         # 预约数据类
├── addclinicdialog.h/cpp     # 添加/编辑门诊对话框
├── addclinicdialog.ui
├── bookdialog.h/cpp          # 预约对话框
├── bookdialog.ui
├── 1.pro                     # Qt 项目文件
└── build_test_clean/         # 构建目录
    └── debug/1.exe           # 可执行文件
```

### 阶段 7：.ui 布局修复

**用户反馈**：在 mainwindow.ui 为什么那么奇怪。

**根因**：之前加了 `buttonRowWidget` QWidget 容器包裹按钮行，无固定高度导致在垂直布局中被无限拉伸，分组框很高、按钮挤在底部。

**修复方案**：
- 移除 `buttonRowWidget` 容器，按钮行布局直接嵌套进主布局（Qt 标准写法）
- 两个 QGroupBox 设置 `vsizetype="Fixed"`
- 查询区域保留在 `queryContainer` 容器中（默认隐藏）

### 阶段 8：代码审查与 Bug 修复

**用户需求**：检查我的代码有什么问题。

**审查结果**：

#### 🔴 严重 Bug
**编辑门诊后 currentCount 归零**
- 位置：`mainwindow.cpp` `on_btnEditClinic_clicked()`
- 原因：`dialog.getClinic()` 返回的 `edited.currentCount = 0`，代码只复制 `appointments` 列表，没同步 `currentCount`
- 后果：编辑后已预约人数归零、剩余号源计算错误、可超额预约

#### 🟡 中等问题
1. `fillQueryCombo` 中 `currentData().toInt()` 对无效 QVariant 返回 0，可能错误选中门诊 0
2. `Clinic::appointments` 为 public，currentCount 封装可被绕过
3. 析构函数中 `saveData()` 可能弹 QMessageBox
4. `BookDialog` 构造函数参数应为 const 引用
5. `loadLegacyTxt` 用默认编码，旧文件 GBK 会乱码

#### 🟢 轻微问题
- 退出时 saveData() 调用两次（按钮+析构）
- const 正确性问题
- `Appointment::age` 默认 0

**修复执行**（用户要求继续修复中等问题）：

1. **严重 Bug 修复**：新增 `Clinic::setAppointments()` 方法，编辑门诊时用 `edited.setAppointments(clinic.appointments)` 替代直接赋值
2. **fillQueryCombo 修复**：增加 `currentData.isValid()` 判断
3. **删除冗余 currentCount**：彻底删掉 `currentCount` 成员变量，`getCurrentCount()` 改为返回 `appointments.size()`，从根源消除数据不一致风险
4. **析构函数静默保存**：`saveData(bool silent = false)` 新增参数，析构调用 `saveData(true)` 不弹框
5. **BookDialog const 正确性**：构造函数参数改为 `const QList<Clinic>&`
6. **loadLegacyTxt 编码**：显式设置 `in.setEncoding(QStringConverter::Utf8)`

**编译验证**：零错误零警告，运行验证通过。

## 五、关键技术决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 数据存储格式 | JSON | 结构化、易读、Qt 原生支持 |
| 原子写入 | QSaveFile | 防止写入中断损坏数据 |
| 门诊号查重 | QHash O(1) | 替代遍历，大数据量下性能更好 |
| 已预约人数 | appointments.size() | 删除冗余 currentCount，从根源消除数据不一致 |
| 表头拉伸 | 构造函数两行代码 | 比提升控件类更简单，用户明确要求 |
| UI 设置 | .ui 文件为主 | 用户要求"主函数不要有 UI 设置"，仅表头拉伸因 .ui 不支持而留代码 |
| 测试方法 | 代码审查+运行时验证 | GUI 自动化工具不可靠，混合方式最可靠 |
